# 运营周报自动化提醒

这是一套用于教学运营团队周报提醒、会后待办确认、下周周报模板整理与飞书写回的自动化流程。

> 公开版说明已移除内部飞书链接、钉钉群 ID、真实成员名单和授权细节。实际运行配置请保存在本地或私有环境中，不建议上传到公开仓库。

## 功能概览

- 每周六提醒团队更新本周运营周报。
- 每周日检查周报状态，对未更新部分进行二次提醒。
- 每周一会议结束后，根据会议记录整理待确认待办。
- 每周一回收确认和修改，生成下一周周报模板。
- 优先通过飞书 API 写回；API 不可用时，可使用当前浏览器编辑态尝试写回；失败时输出可复制草案。

## 自动化时间表

| 时间 | 自动化 | 作用 |
| --- | --- | --- |
| 每周六 18:00 | 周报更新提醒 | 在团队群内发送简化提醒，请大家更新本周周报。 |
| 每周日 12:00 | 周报状态二次提醒 | 读取周报页面状态，只提醒未更新部分；读不到页面时发送通用提醒。 |
| 每周一 13:30 | 会后待办确认 | 根据会议记录整理待确认待办，并发送给团队确认或修改。 |
| 每周一 16:00 | 确认回收与模板整理 | 回收确认/修改回复，整理下一周周报模板并尝试写回。 |

## 标准消息模板

### 更新提醒

```text
【运营周报更新提醒】

请大家今天更新本周运营周报：

{周报链接}

参与人：{参与人列表}
```

### 二次提醒

可读取周报且存在未更新内容时：

```text
【运营周报二次提醒】

截至今天 12:00，以下部分还未看到本周更新，请尽快补齐：

{未更新负责人或分区列表}

周报链接：
{周报链接}
```

如果周报页面无法读取、需要登录、无权限、找不到本周日期标题或页面结构无法可靠解析：

```text
【运营周报二次提醒】

截至今天 12:00，系统暂时无法自动读取飞书运营周报状态。
请还未更新本周运营周报的同学尽快补齐：

{周报链接}
```

### 会后待办确认

```text
【运营周会待办确认】

会议日期：{YYYY-MM-DD}
运营周报链接：
{周报链接}

请大家确认以下运营周会待办：

{负责人/分区}
- {待确认事项1}
- {待确认事项2}

待认领：
- {无法明确归属的事项}

请在群里回复：
确认
或
修改：具体内容
```

### 回收结果

```text
【运营周会确认回收结果】

已确认：
{已确认人员列表}

已修改：
{已提交修改人员及摘要}

未确认：
{未确认人员列表}

下周运营周报草案摘要：

{按负责人/分区整理后的草案摘要}

飞书写回状态：
{已写入飞书 / 写回失败，需要人工复制或补权限}

周报链接：
{周报链接}
```

## 下周周报模板

下周日期标题使用 `YYYY/M/D` 格式，例如：

```text
2026/6/22

上周会议重点待办

一.数据运营-负责人A
- {确认/修改后的待办}

二.demo运营-负责人B
- {确认/修改后的待办}

三.教学教务-负责人C
- {确认/修改后的待办}

四.排课教务-负责人D
- {确认/修改后的待办}

五.组建-负责人E
- {确认/修改后的待办}

六.质量培训-负责人F
- {确认/修改后的待办}

七.质量培训-负责人G
- {确认/修改后的待办}

八.质量培训-负责人H
- {确认/修改后的待办}
```

写入规则：

- 如果下周日期标题不存在，则创建完整下周模板区。
- 如果下周日期标题已存在，则只补齐空分区。
- 已有内容不覆盖。
- 写入后必须能重新读到下周日期标题和分区内容，才算写回成功。

## 文件说明

- `Write-FeishuOperationWeeklyReport.ps1`：飞书 API 写回脚本，默认 dry-run。
- `operation_weekly_report_automation.config.example.json`：公开版配置示例。
- `.gitignore`：避免提交真实配置、草案和日志。

## 飞书写回

API 写回需要配置环境变量：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`

应用还需要具备 Wiki 读取、Docx 读取、Docx 编辑相关权限，并在飞书文档侧被授予可编辑权限。

脚本默认 dry-run，不会修改飞书：

```powershell
.\Write-FeishuOperationWeeklyReport.ps1 -Mode dry-run -ConfigPath .\operation_weekly_report_automation.config.example.json
```

传入回收草案后写入飞书：

```powershell
.\Write-FeishuOperationWeeklyReport.ps1 -Mode write -DraftPath .\operation_next_week_draft.json
```

草案 JSON 可以按分区标题、负责人或别名组织：

```json
{
  "一.数据运营-负责人A": ["事项 1", "事项 2"],
  "负责人D": ["排课教务待办"]
}
```

## 安全说明

不要把以下内容提交到公开仓库：

- 真实飞书链接和 token
- 钉钉群会话 ID 或机器人 Webhook
- 个人访问令牌、授权码、Cookie
- 内部成员名单和联系方式
- 会议记录原文或内部待办详情
